## 〇、一句话诊断

**产线回答的一直是"这条内容和 AI 有关吗"，从没回答过"这条内容值得老张看吗"。**
文案层（机械稿拦截、钩子去冗余）修了四轮，选题层（信源好坏、增量有无）从立项起就没建过。

## 二、根因四层

1. **信源层——求广不求精**：GitHub 话题面/hn/exa 免费源照单全收，无质量分级。漏斗以采集量开头（915→82→5），**数量指标天然鼓励收垃圾**。
2. **选题层——没有读者模型**：全链 LLM 判定（recall reviewer / writer / reviewer）只问"相关吗""通顺吗"，从问"老张知道吗""对他有用吗"。
3. **编辑层——writer 是润色工不是主笔**：钩子是原文摘要复述（「四通道检索融合架构落地」是论文作者自己写的句子），对读者零增量；降级链一断就出机械稿。
4. **反馈层——行为信号只算不用**：Beta 兴趣引擎"第一版只算不放"，老张的展开/冷落从未回流到源权重与选题裁剪。

## 三、整改方案（三阶段，每阶段独立可验收）

### Phase 1 止血：信源白名单重洗（批准后 1 天内）

- 采集清单从"免费可得"改为"策展准入"：**官方一手源**（OpenAI/Anthropic/Google DeepMind/Meta AI/Mistral/Qwen 官博、顶级会议 tracker、arXiv cs.AI+cs.CL 精选分区）、**一线技术媒体**精选 3~5 家。
- 每个源准入须回答：*谁在写这个源，他凭什么比我早知道/知道得多？*
- GitHub 类源设硬门槛：**star ≥ 50** 且非重复造轮子类别（个人教程/合集仓库拒收）。
- **付费/赞助专属内容一票否决**（sponsor-only、付费墙内文不转述）。
- 漏斗指标反转：从"采集 915 条"改为**源通过率**——某源连续 7 天相关通过率 <10% 自动降权归零，看板公示。

### Phase 1.5 工具化扩源：anysearch + agent-reach 全量点亮（老张 09-06 追问补入，1~2 天）

> **定位澄清**：白名单管「准入标准」（任何渠道进来的内容都过同一套增量三问与信源准入），
> 本节管「候选从哪来」。**扩源不稀释质量——质量在闸门，不在渠道数。** 工具化扩源与
> 策展白名单是正交的两层，前者做宽、后者做严。

**现状盘点（09-06 实测）**：
- agent-reach 渠道矩阵 15 渠道仅点亮 5 类（RSS/Exa/GitHub/V2EX/B站/YouTube，33 源），
  其余 9 渠道卡在一次性配置（Jina key / Twitter cookies / opencli 桥）；
- **anysearch 零接入**——它是 HTTP 直连的 MCP server（api.anysearch.com/mcp，匿名免 key
  全功能，已实测），bot 作为 Node 程序可直接 POST 走 MCP 协议，零本地依赖；
- 全部 33 源均为被动拉取/静态查询词，没有任何「按画像主动搜索」的通道。

**三层工具栈（从被动到主动）**：

| 层 | 工具 | 用法 | 前置 |
|---|---|---|---|
| 渠道矩阵 | agent-reach | 点亮 Twitter（AI 圈一手发布地，价值最高）/ Jina 网页兜底 / opencli 桥 6 渠道 | Twitter cookies、Jina key 需一次性配置 |
| 搜索主动层 | **anysearch** | 每轮由读者画像生成 N 组查询（新发布/评测对比/小众高质量），`batch_search` 1–5 路并发，`sub_domains` 锁 tech/academic；`extract` 做命中结果的全文提取（免 key 替代 Jina 兜底） | 无（匿名可跑；日耗 ~15 次远低于免费 key 1000 次/日，上线后注册 key 挂 env） |
| 语义深化 | Exa（已有 9 源） | 静态查询串升级为**画像驱动**（查询词随画像卡迭代，不再是一劳永逸的词表） | 无 |

**与增量三问的协同（这是扩源的核心论据）**：三问之首「他大概率还不知道吗」只有主动
搜索能答——全网刷屏的内容被动渠道必然送到，不需要 bot；**搜索的价值是挖「还没刷屏
但该被知道」的东西**（新发布/新仓库/新论文/未被发现的高质量评测），这正是语义搜索与
垂直域检索的强项。扩源不是回到旧模式的大水漫灌，而是给增量三问供弹。

**实施清单**：
- T1 anysearch 采集器：MCP HTTP client（tools/call: search / batch_search / extract）+
  画像查询生成器 + 结果走既有闸门链（时效预筛→去重→召回判定→终审），新增 source 类型
  `anysearch`，漏斗记账同源级（来源名=查询词）；
- T2 Jina key：免费注册一行 env（或先用 anysearch extract 替代，Jina 降级为可选）；
- T3 Twitter 渠道：等 cookies 配置后点亮（清单见 `docs/channel-matrix-2026-09-04.md`）；
- T4 Exa 查询串画像化（随 Phase 2 画像卡一起落地）。

**需老张配合**：①Twitter cookies（AUTH_TOKEN+CT0，涉及账号必须老张提供或授权注册
专用号）；②（可选）anysearch 免费 API key 注册（`as_sk_...`，匿名也能起步）。

### Phase 2 读者模型 + 增量三问（3~5 天）

- **读者画像卡**（显式配置文件，老张可自行增删）：当前在做/在决策的事（AI 编码工具、端侧推理、多 agent 协作、内容生产基建……由老张审定）、明确不关心的领域。
- **增量三问闸门**：源过了之后、写稿之前，LLM 必须逐条回答——
  1. 这事他大概率还不知道吗？（全网刷屏的 = 不合格）
  2. 和他正在做/正在决定的事相关吗？
  3. 错过它有真实代价吗？（三问皆否 → 丢弃，宁缺毋滥写进代码不写进口号）
- **主笔换声**：钩子从"复述原文"改为"编辑判断"——一句话说清*为什么值得他花时间*；写不出编辑判断的条目不过闸。
- **每日上限**（默认 10 条）：总量封顶，杜绝"凑数薄包"。

### Phase 3 行为反馈闭环（约 1 周）

- interest.json（展开率 Beta 后验）从"只算不放"接上：源权重 = f(展开率、曝光未展开衰减)，每周重排，垫底源出局。
- reviewer 校准数据源从"人工金标 47 条"迭代为**老张真实行为**（展开=正例、多次曝光不展开=负例），校准对齐真口味而非标注员口味。
- 周报：哪些源在真正喂到老张、哪些在吃白食——白名单保持"活策展"，可随时回滚任何源。

## 四、发布纪律（本次的错误不再犯）

- 整改期间发布器维持冻结，产出只落本地 outbox；
- 恢复发布的前置：**老张连续抽验 3 天 outbox 草稿并点头**，才推线上；
- 上线后任何一次"垃圾"判定 → 自动冻结 24h 等修复，不占用人工判断。
