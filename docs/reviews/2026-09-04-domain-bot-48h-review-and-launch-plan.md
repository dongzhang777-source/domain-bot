## 五、一个必须点破的死锁：标定需要数据，数据需要开跑

M6 标定（I-1 的 N、I-3 的分子）deadline 是 09-07，理由是「arXiv 周五/周六无公告」的假红窗口要在开跑前标定掉。

**但标定需要"日节奏"数据（每天 1 轮），而现在手上只有 4 轮观测——且是 09-01 同日 70 分钟内连跑的。**

诊断报告自己承认（`architecture-diagnosis:95` 修订注 M1）：末轮 `candidates=0` 是「同日 70 分钟连跑第 4 轮的产物，**不代表日节奏稳态**；日节奏下每轮 ≈286」。

**死锁**：
- 要标定 → 需要日节奏数据
- 要日节奏数据 → 得先跑几天
- 要跑 → 判定线得先标定完（否则违反"开跑前定死"）

死循环。

### 破局方案（我推荐）：把"等三 key"的死时间变成"标定期"

**关键认识：I-1 和 I-3 是"仪器故障判据"，只依赖采集，不依赖 Telegram。** 而采集 **不需要任何 key**（`README:31`：启发式打分 + 文件推送即可运行）。

所以两条腿可以并行：

```
今天                    09-07 前后              三 key 到位后
  │                        │                        │
  ├─ 老张签判定线 ──────────┤                        │
  ├─ 老张去配三 key ────────┼───────────────────────┤
  │                        │                        │
  ├─ 【标定期】无 key 也能跑 ┤                        │
  │   每天 1 轮采集，        │                        │
  │   攒 3~5 天日节奏数据 ──┤                        │
  │                        ├─ M6 标定完成 ──────────┤
  │                        ├─ I-4 口径对齐 ─────────┤
  │                        │                        ├─ 重置 memory 基线
  │                        │                        ├─ Telegram 真机联调
  │                        │                        └─ 正式开跑（probeStart 生效，计两周）
```

**为什么这个方案划算**：
1. **不花额外时间**——标定期和"等老张配 key"完全重叠，白赚 3~5 天
2. **不违反纪律**——`gen-evidence.mjs` 已有 `--probe-start` 参数，标定期数据会被窗口过滤掉，不进两周窗口；判定线在正式开跑前定死，纪律没破
3. **解决了死锁**——用真日节奏数据做标定，比拿 4 轮连跑数据硬凑可信得多

**代价**：多 3~5 天。但这几天本来也要等 key。

**为什么不建议"等标定完再签"**：因为真正的瓶颈是三 key，不是标定。等标定只会把签字推到 09-07 之后，而那几天反正也在等 key——白白损失并行窗口。

**为什么不建议"带着待定直接签"**：签字的全部意义就是"开跑前定死"。留着"待定"签，等于开跑后还能挑对自己有利的口径——这正是判定线花大力气要防的事。

### 决策 2：中文领域怎么办？（决策点 4）

| 方案 | 做法 | 后果 |
|---|---|---|
| **案 A（我推荐）** | 探针期**禁用** v2ex/bili（改 `enabled=false`，不是删配置），判定线保持"只验证英文领域" | I-3 分母自动排除这两个结构性零产出源，假红风险降低；与矩阵裁决 #5 一致 |
| 案 B | 保留中文源，判定线正式改裁为"验证中英双语领域"，更新 `criteria:64` | 范围蔓延——中文分词（C1）本就是探针期明确不做的项 |

**推荐案 A 的理由**：
1. 实测中文源是结构性零产出（诊断报告明确点名 v2ex/bili）
2. 留着不动 + 判定线写"英文" = 两周后结论措辞会很尴尬（跑了中文源却声明只验证英文）
3. 案 A 用 `enabled=false` 而非删配置，**保留了恢复能力**——加注后想加中文，改回 true 即可
